What I keep walking into

  1. Six document states in the data. None of them on screen.
  2. One font size doing eight jobs.
  3. Every card shouting at the same volume.
  4. Colour used as decoration.
  5. Twelve hundred equal cards and no way to narrow them down.

That is noise. I design by taking it out, then I build what is left.

Noise floor−6 dB

Six filters

Rules I can defend in a review. Each one came out of a screen that failed.

  1. F1

    One accent, and it means tappable

    If colour is decoration it stops being information. The accent is the only saturated thing on the screen.

  2. F2

    Colour carries meaning

    A badge is red because something is wrong, not because the row looked empty.

  3. F3

    Typography does the hierarchy

    Two font sizes doing eight jobs reads as a wall. A real scale tells you what to read first.

  4. F4

    Light and dark are both designed

    Dark mode is not an inverted stylesheet. Surfaces, borders and emphasis change with it.

  5. F5

    43 pixels is not a tap target

    Controls get 44px minimum and 16px text on mobile, so iOS never zooms the input.

  6. F6

    Revise, do not stack

    Patches on top of patches produce screens nobody can reason about. If it is wrong structurally, rebuild it.

T—01

LedgerDesk

Document operations platform · 2026 · Design and front end

Accounting teams were reviewing client documents through email and spreadsheets. I designed the review surface: one queue, one set of states, no ambiguity about what is done and what is not.

Problem
Six document states existed in the data and none of them existed on screen. Reviewers were guessing.
Decision
Numbers carry the meaning. Pending, punched and invalid each get a value and a colour from one token table. Navigation, tables and dialogs all read from the same tokens.
Result
Light and dark share one layout. Body text checked at 4.5:1. A 16 hour review cycle became a queue with a visible end.
T—02

Tripp’in AI

Travel planner · 2026 · Design system, web UI, Android UI · Source

A travel planner that produces a fixed itinerary instead of a chat answer. The hard part was making a dense plan readable, so I gave it the visual language of a flight briefing: numbered steps, form headers, one accent, physical depth instead of shadows.

Problem
One font size did eight jobs. Colour was decoration. Every card shouted at the same volume, so nothing read as important.
Decision
I wrote the design system before touching screens: colour carries meaning and nothing else, a type scale with real steps, one accent for anything tappable.
Result
The system is enforced, not admired. Every token has a rule, a value and a contrast check, and Android and web use the same table.
T—03

God’s Eye View

Satellite imagery analysis console · 2026 · Interface design · Open source

An analyst tool that pulls imagery for a place and a date range. Dense by necessity: coordinates, sensor metadata, capture history and the image itself all have to be visible at once without crowding each other.

Problem
Analysts cross reference numbers while looking at an image. A layout that hides either one costs them the task.
Decision
Fixed panels, no floating windows. Numeric values in monospace so they line up when scanned. One accent reserved for the active selection.
Result
A console that stays quiet while the data is loud. Readable at a glance, still readable at 2am.
T—04

AI Tools Directory

Public directory · 2026 · Design and build · Live

Curated AI tools, searchable and categorised. The design problem is scanning speed: a visitor arrives with a task in mind and needs categories, previews and filters without reading a paragraph first.

0+ tools, still scannable
Problem
Directories fail the same way: too many equal cards and no way to narrow down.
Decision
Filters above the fold, one card pattern, one accent for the interactive state, and the count always visible so a visitor knows the size of the list.
Result
A 1,200 item list that stays scannable on a phone and on a laptop.
